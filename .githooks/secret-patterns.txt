# Padrões GENÉRICOS que barram o commit. Três campos separados por `%%`:
#
#     rótulo %% regex %% caminhos-isentos
#
# O separador não é `|` porque os próprios regex usam `|` para alternância.
# O terceiro campo pode ficar vazio.
#
# Comparado apenas contra as linhas ADICIONADAS no índice: remover uma ocorrência
# antiga nunca é barrado.
#
# ---------------------------------------------------------------------------
# ESTE ARQUIVO É VERSIONADO E PÚBLICO. Por isso guarda só o que vale para
# qualquer instalação — chave, hash, token, IP privado, MAC.
#
# Os padrões da SUA topologia (hostname de equipamento, domínio, faixa de rede
# própria) vão em `secret-patterns.local.txt`, que é gitignorado. Uma lista de
# termos proibidos publicada no repositório entrega de graça o esquema de nomes
# e confirma quais nomes importam — protegeria contra o vazamento acidental ao
# custo de fazer o vazamento deliberado.
#
#     cp .githooks/secret-patterns.local.txt.example \
#        .githooks/secret-patterns.local.txt
#
# O `pre-commit` carrega os dois e avisa quando o local não existe.
# ---------------------------------------------------------------------------
#
# O terceiro campo existe porque alguns desses valores são legítimos em lugares
# específicos — o plano de VLANs precisa declarar gateways, os templates de rede
# descrevem a topologia atual, e os `.example` existem para mostrar o formato.
# Isenção por caminho é explícita e revisável; supressão inline não seria.

chave privada%%-----BEGIN [A-Z ]*PRIVATE KEY-----%%^\.githooks/
chave SSH pública real%%ssh-(rsa|ed25519|dss) AAAA[A-Za-z0-9+/]{40}%%\.example$|^\.githooks/
hash de senha unix%%\$(2[aby]|5|6)\$[./A-Za-z0-9]{12}%%\.example$|^\.githooks/
token hexadecimal de 64%%[^a-f0-9/][0-9a-f]{64}[^a-f0-9]%%\.lock\.hcl$|^\.githooks/
# A isenção de `^docs/` foi REMOVIDA daqui, e não deve voltar. Ela existiu por
# pouco tempo, com o argumento de que documentação "só descreve" — e foi
# exatamente por ela que uma senha literal em texto puro atravessou o gate e
# ficou versionada num roadmap. O gate cobre `docs/` como cobre qualquer outro
# diretório: um segredo escrito em markdown vaza igual a um escrito em YAML.
senha literal%%(password|passwd|secret|api[_-]?key|token)[[:space:]]*[:=][[:space:]]*["']?[^$"'{[:space:]#][^"'[:space:]#]{11}%%\.example$|^\.githooks/

# Senha fraca SOLTA, sem a palavra `password:` antes dela. O padrão acima só
# dispara quando existe um rótulo (`password=`, `token:`) — e a senha que vazou
# aqui estava no meio de uma frase em prosa, citada entre crases, sem rótulo
# nenhum. Este pega a forma, não o contexto.
#
# Calibragem, porque falso positivo treina a pessoa a usar `--no-verify`, o que
# é pior que não ter o padrão:
#   - as bordas recusam `[:alnum:]`, então `123456` dentro de um digest
#     `sha256:` ou de um hash hexadecimal NÃO casa — não há delimitador ali;
#   - a borda esquerda recusa `<`, `{` e `$`, e a direita `>` e `}`, para não
#     acusar placeholder de exemplo (`<CHANGEME>`, `${CHANGEME}`);
#   - `admin` exige 3+ dígitos: `admin1` seria ruído em nome de host ou índice.
senha fraca literal%%(^|[^[:alnum:]<{$_-])(admin[0-9]{3,}|senha[0-9]+|123456[0-9]*|changeme|password[0-9]+|passw0rd|qwerty[0-9]*|letmein)([^[:alnum:]>}_-]|$)%%\.example$|^\.githooks/

# `IaC/ansible/tests/fixtures/opnsense.yml` é isento aqui: usa a faixa de MAC
# de documentação da IANA (00:00:5e:00:53:xx) para provar que o harness de
# render (IaC/ansible/tests/render_opnsense.py) funciona fora da caixa. Isenção
# por ARQUIVO, não por diretório — o ERE do grep não tem lookahead negativo
# para distinguir MAC de documentação de MAC real, então cada fixture novo sob
# tests/fixtures/ que precisar de MAC tem que ser acrescentado aqui de
# propósito, um por um. Nunca isente o diretório inteiro: isso abriria a porta
# para qualquer MAC real em qualquer arquivo futuro ali dentro.
endereço MAC%%([0-9a-fA-F]{2}:){5}[0-9a-fA-F]{2}%%^\.githooks/|^prod-snapshot/|^IaC/ansible/tests/fixtures/opnsense\.yml$
